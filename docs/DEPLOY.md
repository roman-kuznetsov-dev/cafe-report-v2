# Развёртывание на Streamlit Cloud

Инструкция по развёртыванию веб-версии приложения на бесплатном
хостинге [Streamlit Cloud](https://streamlit.io/cloud).

## Требования

- Аккаунт GitHub.
- Аккаунт Streamlit Cloud (регистрация через GitHub).
- Репозиторий с кодом проекта.

## Подготовка репозитория

Streamlit Cloud устанавливает зависимости из указанного файла.
В репозитории присутствуют два файла зависимостей:

- `requirements.txt` — для локальной разработки и CI.
- `requirements-streamlit.txt` — минимальный набор для веб-версии.

Для деплоя используется `requirements-streamlit.txt` — его нужно
указать в настройках приложения.

## Шаги развёртывания

### 1. Регистрация

1. Открыть https://streamlit.io/cloud
2. Нажать **Sign up** → **Continue with GitHub**.
3. Разрешить доступ к аккаунту GitHub.
4. После входа — открывается список приложений.

### 2. Создание приложения

1. Нажать **New app**.
2. Указать параметры:
   - **Repository:** `<логин>/cafe-report-v2`.
   - **Branch:** `main`.
   - **Main file path:** `app.py`.
3. Открыть **Advanced settings**.
4. В поле **Requirements file** указать:
requirements-streamlit.txt
5. Нажать **Deploy**.

### 3. Первый запуск

Streamlit Cloud выполняет:

1. Скачивание кода из GitHub.
2. Установку зависимостей (2–3 минуты).
3. Запуск приложения.

После завершения приложение доступно по адресу:
https://<логин>-cafe-report-v2.streamlit.app

### 4. Проверка

1. Открыть ссылку приложения.
2. Загрузить тестовый файл `cafe_data.xlsx`.
3. Проверить работу вкладок, графиков, экспорта.

## Обновление приложения

**Автоматическое.** При push в ветку `main` Streamlit Cloud
перезапускает приложение (30–60 секунд).

**Ручное.** В панели приложения — кнопка **Rerun**.

## Настройки

### Ограничения бесплатного тарифа

| Параметр | Значение |
|----------|----------|
| RAM | 1 GB |
| CPU | 1 ядро |
| Доступ | публичный (по ссылке) |
| Активация после простоя | автоматическая |

### Засыпание при неактивности

При отсутствии посещений в течение **7 дней** приложение переходит
в спящий режим. При следующем запросе — восстанавливается за
10–30 секунд.

Для предотвращения засыпания используется внешний сервис
мониторинга (например, [UptimeRobot](https://uptimerobot.com/)),
который периодически отправляет запрос на URL приложения.
